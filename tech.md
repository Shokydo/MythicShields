Ниже — полноценный `.md`-файл технического задания. Я учёл твоё главное требование: кастомный предмет должен **по-настоящему** переводить игрока в состояние `isBlocking()`, чтобы условие `blocking` в MythicMobs (и `?blocking` в строке скилла, например `~onPressF ?blocking`) работало без костылей с таймерами и аурами.

```markdown
# Техническое задание: аддон «MythicShields»

## 1. Цель

Создать аддон для **MythicMobs** (с опциональной поддержкой **MythicCrucible**), который позволяет **любому предмету** выполнять роль **ванильного щита**:

- Игрок зажимает ПКМ → предмет «поднимается», игрок входит в состояние блокировки (`HumanEntity#isBlocking() == true`).
- Пока игрок блокирует, **условие `blocking` в MythicMobs возвращает `true`**.
- Скиллы с `?blocking` (например, `~onPressF ?blocking`) **корректно запускаются**.
- У щита есть настраиваемая **прочность / стамина / HP**, **регенерация**, **кулдаун на поднятие**, **резисты** и опциональная **блокировка способностей**.

Ключевая проблема, которую решает аддон: стандартный предмет MythicMobs (даже с `Id: IRON_SHIELD`) не всегда ведёт себя как ванильный щит с точки зрения `isBlocking()`, если он выдан через MythicMobs/Crucible. Аддон гарантирует, что состояние блокировки **реально устанавливается** и **корректно снимается**.

---

## 2. Ключевое требование: `blocking` должен работать «из коробки»

### 2.1. Как это работает в MythicMobs сейчас

Условие `blocking` проверяет `HumanEntity#isBlocking()`:

```yaml
Conditions:
  - blocking true
```

Если `isBlocking()` возвращает `false`, условие не проходит, и скилл с `?blocking` **не запускается**.

### 2.2. Что должно происходить с кастомным щитом

Для любого предмета с `Shield.Enabled: true` аддон обязан обеспечить:

1. При начале использования предмета (зажатие ПКМ) → `player.isBlocking()` становится `true`.
2. При отпускании ПКМ или прерывании использования → `player.isBlocking()` становится `false`.
3. Пока `isBlocking() == true`, **условие `blocking` в MythicMobs проходит**, и любой скилл с `?blocking` может выполниться.

**Пример, который должен работать:**

```yaml
# Предмет (может быть любым, не обязательно SHIELD)
MyShieldWeapon:
  Id: NETHERITE_SWORD
  Skills:
    - skill{s=shieldAttack} @self ~onPressF ?blocking
```

```yaml
shieldAttack:
  Skills:
    - damage{amount=10} @target
    - message{m="&aАтака через щит!"} @self
```

> Аддон **не должен** заставлять пользователя вручную вешать `~onTimer` и проверять переменные. Состояние блокировки должно быть **нативным** для Bukkit/Paper.

## 3. Функционал предмета-щита

### 3.1. Блок `Shield` в конфигурации предмета

```yaml
MyCustomShield:
  Id: IRON_SHIELD # или любой другой материал
  Display: '<gold>Кастомный Бастион</gold>'
  Shield:
    Enabled: true
    # ... параметры ...
```

Если `Shield.Enabled: false` или блока нет — предмет ведёт себя как обычный предмет MythicMobs.

### 3.2. Прочность щита (Durability)

Щит имеет собственную шкалу прочности, независимую от ванильной прочности предмета (или использующую её — на выбор в конфиге).

```yaml
Shield:
  Enabled: true
  Durability:
    # Максимальная прочность. Поддерживает переменные MythicMobs.
    Max: '100 + <caster.var.shield_tier> * 25'
    # Сколько прочности тратится за один заблокированный удар.
    CostPerBlock: '2'
    # Порог, при котором щит ломается (перестаёт блокировать).
    BreakThreshold: 0
    # Поведение при поломке:
    #   BREAK_ITEM       — предмет уничтожается
    #   STAY_BROKEN      — предмет остаётся, но не блокирует до ремонта
    #   DROP_TO_INVENTORY — предмет падает в инвентарь (если возможно)
    OnBreak: 'STAY_BROKEN'
```

**Требования:**
- Поддержка выражений с `<caster.var.*>`, `<skill.var.*>`, `<target.var.*>` и базовой арифметики.
- Если выражение не парсится — использовать безопасное значение по умолчанию и писать предупреждение в лог.
- Прочность **не тратится**, если удар был полностью проигнорирован (например, `ignoreshield` или нулевой урон).

### 3.3. Альтернативный ресурс: стамина / HP / переменная

Вместо или вместе с прочностью можно использовать кастомный ресурс.

```yaml
Shield:
  Enabled: true
  Resource:
    # DURABILITY — стандартная прочность (см. выше)
    # STAMINA    — стамина через MMOCore (или другой провайдер)
    # HP         — здоровье игрока (не убивает, опускает до 1 HP)
    # VARIABLE   — переменная MythicMobs (например, <caster.var.stamina>)
    Type: 'STAMINA'
    # Сколько ресурса тратится за блок.
    CostPerBlock: '5 + <caster.var.shield_weight>'
    # Если ресурса не хватает — блок не даёт резиста (урон проходит).
    RequireOnBlock: true
    # Минимальный запас, при котором блокировка ещё возможна.
    MinResource: 1
```

**Интеграция:**
- `STAMINA` — через soft-depend на MMOCore (или аналогичный плагин). Если провайдера нет — ресурс игнорируется с предупреждением в лог.
- `HP` — списывает здоровье игрока, но **не может убить** (минимум 1 HP).
- `VARIABLE` — чтение/запись переменной MythicMobs через API.

### 3.4. Регенерация

```yaml
Shield:
  Enabled: true
  Regen:
    # Сколько восстанавливается за тик регенерации.
    Amount: '0.5'
    # Интервал регенерации в тиках.
    Interval: 40
    # Задержка после последнего блока перед началом регенерации (тики).
    DelayAfterBlock: 60
    # Работает ли регенерация, пока щит поднят (в блоке).
    RegenWhileBlocking: false
```

### 3.5. Кулдаун на поднятие щита

После того как щит был опущен (или сломан), его нельзя поднять снова в течение заданного времени.

```yaml
Shield:
  Enabled: true
  RaiseCooldown:
    # Кулдаун на поднятие щита после опускания (тики). 0 = без кулдауна.
    Ticks: 40
    # Кулдаун после поломки щита (тики). Переопределяет Ticks, если щит сломан.
    OnBreakTicks: 100
```

**Требования:**
- Кулдаун **индивидуален для каждого игрока**.
- Если игрок пытается поднять щит на кулдауне — блокировка **не активируется**; встроенное сообщение не отправляется. Пользовательские уведомления можно реализовать через MythicMobs Skills.
- Кулдаун **не сбрасывается** при переключении предмета в руке (если это тот же самый щит).

### 3.6. Резисты и модификаторы урона

```yaml
Shield:
  Enabled: true
  Blocking:
    # Глобальное снижение урона при блоке (0.0–1.0).
    DamageReduction: '0.3'
    # Резисты по типам урона (переопределяют глобальный).
    Resistances:
      ENTITY_ATTACK: 0.4
      PROJECTILE: 0.6
      FIRE: 0.2
      MAGIC: '0.1 + <caster.var.magic_resist>'
    # Множитель урона, проходящего сквозь щит.
    DamageMultiplier: 0.9
    # Снижение отбрасывания (0.0–1.0).
    KnockbackResistance: 0.7
```

**Поведение:**
- При событии блокировки (`EntityDamageByEntityEvent` + `player.isBlocking()`) аддон перехватывает урон.
- Сначала применяется `Resistances` для конкретного типа урона (если указан), иначе — `DamageReduction`.
- Затем — `DamageMultiplier`.
- Итоговый урон **не может быть отрицательным** (лечение от урона не допускается, если не включена отдельная опция).

> Ванильный щит даёт 100% блокировку большинства атак. Если `DamageReduction`/`Resistances` заданы, аддон **переопределяет** ванильное поведение, позволяя пропускать часть урона.

### 3.7. Блокировка способностей

```yaml
Shield:
  Enabled: true
  AbilityBlock:
    # Блокировать все скиллы MythicMobs, пока игрок блокирует.
    BlockAllWhileBlocking: false
    # Список ID скиллов, которые нельзя использовать в блоке.
    BlockedSkills:
      - 'Fireball'
      - 'Charge'
    # Кулдаун после опускания щита, в течение которого скиллы тоже заблокированы.
    CooldownAfterBlock: 20
```

**Важно:** это **не должно** мешать условию `blocking` на других скиллах. Если скилл не входит в `BlockedSkills` и `BlockAllWhileBlocking: false` — он должен спокойно запускаться через `?blocking`.

## 4. Техническая реализация состояния блокировки

### 4.1. Случай 1: предмет имеет тип `SHIELD`

Если `Id` предмета — `SHIELD` (или другой предмет, который ванильно поддерживает блокировку), Bukkit сам устанавливает `isBlocking() == true` при зажатии ПКМ. Аддон в этом случае:

- Не вмешивается в процесс блокировки, если не нужно переопределять резисты.
- Может «оборачивать» событие блокировки для применения своих резистов и расхода прочности.

### 4.2. Случай 2: предмет **не** типа `SHIELD` (меч, кирка и т.д.)

Это основной сценарий, ради которого создаётся аддон. Чтобы заставить `isBlocking()` возвращать `true` для произвольного предмета, аддон использует один из подходов (выбор за разработчиком, но в ТЗ фиксируем требование):

**Подход A (предпочтительный): NMS / Paper API**

- При `PlayerInteractEvent` с `Action.RIGHT_CLICK_AIR`/`RIGHT_CLICK_BLOCK` и предметом с `Shield.Enabled: true`:
  - Установить активный предмет игрока через NMS (`EntityLiving#setActiveItem` или аналог).
  - Убедиться, что `isBlocking()` начинает возвращать `true`.
- При отпускании ПКМ или прерывании — очистить активный предмет (`clearActiveItem()`), чтобы `isBlocking()` стал `false`.

**Подход B (резервный): эмуляция через флаги**

- Если NMS-подход невозможен на целевой версии, аддон может поддерживать **собственный флаг** блокировки и **патчить** проверку `blocking` (если MythicMobs позволяет переопределять условия) или использовать `Player#setCooldown`/метаданные.
- Однако это менее надёжно, поэтому в ТЗ основной считается **Подход A**.

### 4.3. Требования к состоянию блокировки

- `isBlocking()` должен становиться `true` **синхронно** с началом использования предмета (или с задержкой не более 1–2 тиков).
- `isBlocking()` должен становиться `false` **синхронно** с отпусканием ПКМ / прерыванием использования.
- Если игрок переключает слот или предмет ломается — блокировка должна **принудительно сниматься**.
- Состояние блокировки **не должно «залипать»** после смерти, выхода из игры или телепортации.

### 4.4. Совместимость с `~onShieldBlock`

MythicCrucible/ MythicEnchants предоставляют триггер `~onShieldBlock`. Аддон **не должен** отменять или дублировать этот триггер. Если предмет с `Shield.Enabled: true` блокирует атаку, триггер `~onShieldBlock` должен срабатывать как обычно (если MythicCrucible установлен). Аддон лишь **дополняет** поведение (расход прочности, резисты), но не ломает существующие механики.

## 5. Технические требования

### 5.1. Совместимость

- **MythicMobs** 5.x (актуальная стабильная ветка).
- **MythicCrucible** — не конфликтовать с `~onShieldBlock` и другими триггерами.
- **MythicEnchants** — не отменять чужие скиллы на `onShieldBlock`.
- **PlaceholderAPI** — для парсинга внешних плейсхолдеров (опционально).
- **MMOCore** — soft-depend для стамины.

### 5.2. Производительность

- Парсинг выражений кэшировать на уровне предмета/игрока.
- Обработка события блокировки — не более 1–2 мс на событие.
- Не вызывать тяжёлые API-методы внутри часто вызываемых событий.

### 5.3. Конфигурация и логирование

- Ошибки парсинга — в `logs/mythicshields.log` с указанием предмета и игрока.
- Команда `/mythicshields reload` для перезагрузки без рестарта.
- Глобальный `config.yml` аддона: отладка, значения по умолчанию, интервал регенерации.

## 6. Пример полной конфигурации

```yaml
BastionShield:
  Id: IRON_SHIELD # или NETHERITE_SWORD, если нужен нестандартный щит
  Display: '<gold>Бастион</gold>'
  Lore:
    - '<gray>Прочность: <white><caster.var.shield_durability></white></gray>'
  Shield:
    Enabled: true

    Durability:
      Max: '80 + <caster.var.shield_tier> * 20'
      CostPerBlock: '2'
      BreakThreshold: 0
      OnBreak: 'STAY_BROKEN'

    Resource:
      Type: 'DURABILITY' # или STAMINA / HP / VARIABLE
      RequireOnBlock: true

    Regen:
      Amount: '1'
      Interval: 60
      DelayAfterBlock: 40
      RegenWhileBlocking: false

    RaiseCooldown:
      Ticks: 40
      OnBreakTicks: 100

    Blocking:
      DamageReduction: '0.35'
      Resistances:
        PROJECTILE: 0.5
        ENTITY_ATTACK: '0.4 + <caster.var.melee_resist>'
      DamageMultiplier: 0.9
      KnockbackResistance: 0.7

    AbilityBlock:
      BlockAllWhileBlocking: false
      BlockedSkills:
        - 'Dash'
        - 'Fireball'
      CooldownAfterBlock: 10
```

## 7. Критерии приёмки

1. Предмет с `Shield.Enabled: true` при зажатии ПКМ **фактически блокирует**: `player.isBlocking() == true`.
2. Условие `blocking` в MythicMobs **возвращает `true`**, пока игрок держит блок этим щитом.
3. Скилл вида `- skill{s=shieldAttack} @self ~onPressF ?blocking` **корректно запускается**, пока щит поднят.
4. Прочность/стамина/HP **тратится** на `CostPerBlock` за каждый заблокированный удар.
5. При достижении `BreakThreshold` щит **перестаёт блокировать** (или ломается — согласно `OnBreak`).
6. Регенерация восстанавливает ресурс с учётом `DelayAfterBlock` и `RegenWhileBlocking`.
7. Кулдаун на поднятие **блокирует повторный подъём** на заданное время и отправляет сообщение.
8. При `RaiseCooldown.OnBreakTicks` после поломки щит нельзя поднять дольше, чем обычно.
9. Аддон **не конфликтует** с `~onShieldBlock` из MythicCrucible/Enchants.
10. Выражения с `<caster.var.*>` корректно вычисляются; при ошибке — безопасное значение по умолчанию.
11. Состояние блокировки **не «залипает»** после смерти, выхода из игры или смены предмета.
